# DevKit 第一版需求

版本：v1.0 草案 · 更新：2026-10-28 · 状态：第一版实现已落地，发布验收进行中（见 verification.md）

## 1. 产品目标

为开发工程师提供随手可用的网页工具：不用在多个网站切换，不重复填写常用参数，不上传源代码、Token 和业务数据。

核心路径：搜索工具 → 粘贴输入 → 调整参数 → 查看结果 → 复制或下载。首页展示收藏、最近使用与分类入口，不设置营销介绍页。

目标平台：现代桌面浏览器，兼容移动端基础使用。第一版无账号、无后端、无收费、无桌面客户端、无远程请求代理。第一版支持简体中文（zh-CN）与英文（en），首次按浏览器语言选择，不支持的语言回退简体中文；用户手动选择优先。代码术语与标准名称保留英文。

## 2. 信息架构与范围

第一版共 **7 类、39 个工具入口**；此前功能讨论中的“42 个”和“8 个分类”属于计数偏差，站点通用能力不计入工具。相关转换在同一工具中分标签或模式，不为每个算法建立独立入口。

所有工具位于 `/tools/<slug>`。分类、排序和搜索别名来自同一份工具注册表。

## 3. 通用需求

- 全局搜索：⌘/Ctrl+K；按名称、slug、别名搜索；支持中文、JSON、base64、timestamp 等；收藏和最近使用加权。
- 收藏可排序；最近使用只保存工具 ID 和访问时间，默认最多 20 项。
- 工具注册表包含 id、slug、分类、排序、名称、描述、关键词、加载器、能力说明；所有页面提供示例、空态、重置、结果复制和适用的下载。
- 主题：浅色/深色/跟随系统；偏好保存本地。桌面双栏，移动端堆叠，代码区可横向滚动。
- 数据：输入默认仅存在内存。普通工具可主动开启草稿保存，说明保存范围、提供清除；AES、HMAC、JWT、cURL 的输入不进入持久存储。刷新默认丢弃输入，站内切换可保留当前会话草稿。
- 默认不设遥测、远程字体、CDN 运行依赖、内容上报或外部 API。错误日志不得含输入、输出、密钥、JWT 或文件名。
- 用户输入不写 URL；可分享工具地址及非敏感设置，需白名单验证。禁止解析网址即自动访问。
- 文件在本地读取，下载使用明确扩展名、编码和文件名，不要求文件系统权限。
- Service Worker 缓存站点壳与静态资源；工具按需缓存。离线可用范围应与缓存状态一致；提供“下载离线资源”以及缓存清理，更新有提示，不强制刷新丢失输入。

## 4. 性能与兼容验收

- 首次支持当前及前一个主要版本的 Chrome、Edge、Firefox、Safari；验收时记录具体版本。基线包含 Clipboard、Web Crypto、Worker、BigInt；可选能力使用特性检测与降级。
- Web Crypto 等能力要求 HTTPS 或 localhost；不可用时显示原因。Clipboard 失败提供手动选择复制。
- 初始传输 JS 目标 gzip ≤ 250 KB；编辑器、格式器、混淆器和各工具依赖按需加载。首页不加载所有工具。
- 常规输入 100 KB 下交互反馈目标 ≤ 100 ms；耗时结果不承诺固定完成时间。超过 150 ms 展示处理中，长任务可取消。
- 编辑器默认上限 5 MiB，文件哈希默认 100 MiB；批量条数受各工具限制。超限在处理前告知。哈希大文件应分块，所选算法无法流式处理时说明内存限制。
- Worker 使用任务 ID，取消或旧结果不得覆盖新输入。用 1 MiB/5 MiB 文本及 100 MiB 文件做专项测量，记录设备与耗时。
- WCAG 2.2 AA 作为可访问性目标；完整键盘操作、可见焦点、屏幕阅读器标签、减少动态效果与非颜色错误提示。

## 5. 分阶段实现与完成条件

第一版包含上述全部 39 个入口，可分批实现，不得将批次完成等同于整版完成。

1. 基础框架、主题、注册表、导航、搜索；JSON 格式化、Base64、时间戳、颜色工作台验证共享组件。
2. 完成其余数据、编码、时间、文本工具。
3. 完成其余 CSS、接口、生成器工具，补齐混淆、离线缓存与跨浏览器验证。

每个工具完成条件：实现所有约定模式；正常/空输入/非法输入/边界可验证；结果可复制；适用时能下载；取消与旧结果处理正确；键盘可达；主题与移动布局通过检查；隐私行为符合约定。

整版完成条件：39 个路由可用、无占位功能；类型检查/格式检查/lint/构建通过；算法有标准向量或可靠样例验证；核心链路端到端通过；离线和无内容外发经过网络面板验证；对比图检查设计一致性。第一版不要求其他语言、登录、云同步、远程请求执行、RSA、完整 IDE、图片处理或任意代码运行。

## 6. 第一版多语言需求

### 范围与选择

第一版仅支持简体中文（zh-CN）和英文（en）；后续语言使用相同资源结构扩展，不预留未翻译的语言选项。两种语言提供完整核心体验，不采用部分页面英文、错误信息中文的混合交付。

语言选择顺序：用户已保存的手动偏好 → 浏览器首选语言列表中首个受支持语言 → zh-CN。zh 系列映射为 zh-CN，en 系列映射为 en；此映射不表示支持繁体中文。设置中可恢复自动选择。语言偏好只保存语言代码。

### 文案范围

- 翻译：首页、分类、工具名称/说明、搜索别名、参数标签、按钮、提示、错误、空态、状态、设置、离线提示及无障碍标签。39 个工具均覆盖。
- 页面标题、可读日期、相对时间、数量和复数按语言格式化；时间与时区选择不随语言切换而改变。
- 不翻译用户输入、代码、JSON 键值、算法名称、URL、标准技术标识与生成代码。示例说明翻译，示例数据内容保持稳定。
- 第三方解析错误统一映射为本地化错误摘要；可折叠展示原始技术详情，不擅自翻译代码片段或行列值。
- 日期解析不猜测 01/02/2026 等歧义文本；继续采用显式格式/标准输入。格式化数字不改变可复制的机器结果。

### 切换与验收

- 顶栏提供语言入口，以“简体中文 / English”显示语言名称，不使用国旗代替语言。
- 切换立即生效，无整页刷新；保留输入、参数、结果、焦点和未完成任务。运行结束后按当前语言显示提示。
- URL 保持 /tools/<slug>，不增加语言前缀，不在 URL 写入输入；更新 document.documentElement.lang 与页面标题。
- 搜索同时索引中英文名称和别名，按当前语言显示结果；收藏/最近使用存稳定工具 ID。
- CI 校验两种语言的 key 和插值占位符一致；缺失 key 开发时告警，生产回退 zh-CN，不直接展示 key。
- 验收两种语言的全部工具主流程、错误和长文案布局；语言切换不触发转换、不丢输入、不改变结果字节内容。首次检测、手动覆盖、刷新恢复和不支持语言回退均可验证。
